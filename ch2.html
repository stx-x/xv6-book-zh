第 2 章　页表 ​

页表是操作系统用来控制内存地址含义的机制。它们使 xv6 能够把不同进程的地址空间多路复用到同一块物理内存上，并保护不同进程的内存。页表提供的这层间接性带来了许多巧妙的技巧。xv6 主要用页表来多路复用地址空间和保护内存。它还使用了几个简单的页表技巧：在多个地址空间中映射同一块内存（内核）、在一个地址空间中多次映射同一块内存（每个用户页也被映射到内核的物理内存视图中），以及用一个未映射的页来守护用户栈。本章余下部分解释 x86 硬件提供的页表以及 xv6 如何使用它们。与现实世界的操作系统相比，xv6 的设计限制较多，但它确实说明了关键思想。

分页硬件 ​

提醒一下，x86 指令（用户和内核的）操作的是虚拟地址。机器的 RAM，即物理内存，用物理地址来索引。x86 页表硬件把这两类地址连接起来，把每个虚拟地址映射到一个物理地址。

从逻辑上说，一张 x86 页表是一个包含 2^20（1,048,576）个页表项（PTE）的数组。每个 PTE 包含一个 20 位的物理页号（PPN）和一些标志位。分页硬件用虚拟地址的高 20 位在页表中索引，找到相应的 PTE，并用 PTE 中的 PPN 替换该地址的高 20 位，从而完成地址转换。分页硬件把低 12 位从虚拟地址原样复制到转换后的物理地址。因此，页表使操作系统能够以 4096（2^12）字节的对齐块为粒度控制虚拟地址到物理地址的转换。这样的一个块称为页。

如 图 2-1 所示，实际的转换分两步进行。页表在物理内存中以两级的树形结构存储。树的根是一个 4096 字节的页目录，其中包含 1024 个类似 PTE 的引用，指向页表页。每个页表页是一个包含 1024 个 32 位 PTE 的数组。分页硬件用虚拟地址的高 10 位选择一个页目录项。如果该页目录项存在，分页硬件就用虚拟地址接下来的 10 位，从该页目录项所指的页表页中选择一个 PTE。如果页目录项或 PTE 不存在，分页硬件就产生一个错误。这种两级结构使页表在大片虚拟地址没有映射的常见情况下，可以省略整个页表页。

每个 PTE 都包含标志位，告诉分页硬件相应的虚拟地址可以如何使用。PTE_P 指示该 PTE 是否存在：如果未置位，访问该页就会产生错误（即不被允许）。PTE_W 控制是否允许指令向该页写入；如果未置位，则只允许读取和取指令。PTE_U 控制是否允许用户程序使用该页；如果清零，则只允许内核使用该页。图 2-1 展示了这一切是如何工作的。这些标志以及所有其他与页表硬件相关的结构都定义在 mmu.h 中。

关于术语的几点说明。物理内存指的是 DRAM 中的存储单元。一个字节的物理内存有一个地址，称为物理地址。指令只使用虚拟地址，分页硬件把它转换为物理地址，然后发送给 DRAM 硬件以读写存储单元。在这个讨论层次上，并不存在“虚拟内存”这种东西，只有虚拟地址。

进程地址空间 ​

entry 创建的页表只有足够让内核的 C 代码开始运行的映射。然而，main 立即通过调用 kvmalloc (1840) 换到一张新页表，因为内核有一套更精细的方案来描述进程地址空间。

每个进程都有一张单独的页表，xv6 在进程之间切换时，会让页表硬件切换页表。如 图 2-2 所示，进程的用户内存从虚拟地址零开始，最多可以增长到 KERNBASE，使进程最多可以寻址 2 GB 内存。文件 memlayout.h 声明了 xv6 内存布局的常量，以及把虚拟地址转换为物理地址的宏。

当进程向 xv6 申请更多内存时，xv6 先找到空闲的物理页来提供存储，然后把指向这些新物理页的 PTE 加入进程的页表。xv6 在这些 PTE 中设置 PTE_U、PTE_W 和 PTE_P 标志。大多数进程不会使用整个用户地址空间；xv6 在未使用的 PTE 中让 PTE_P 保持清零。不同进程的页表把用户地址转换到不同的物理内存页，因此每个进程都有私有的用户内存。

xv6 在每个进程的页表中都包含内核运行所需的全部映射；这些映射都位于 KERNBASE 之上。它把虚拟地址 KERNBASE:KERNBASE+PHYSTOP 映射到 0:PHYSTOP。这样映射的原因之一是内核可以使用自己的指令和数据。另一个原因是内核有时需要能够写入指定的物理内存页，例如在创建页表页时；让每个物理页都出现在一个可预测的虚拟地址上，使这件事很方便。这种安排的缺陷是 xv6 无法使用超过 2 GB 的物理内存，因为地址空间的内核部分就是 2 GB。因此，xv6 要求 PHYSTOP 小于 2 GB，即使计算机拥有超过 2 GB 的物理内存。

一些使用内存映射 I/O 的设备出现在从 0xFE000000 开始的物理地址处，因此 xv6 的页表包含对它们的直接映射。于是，PHYSTOP 必须小于 2 GB 减去 16 MB（用于设备内存）。

xv6 不在 KERNBASE 之上的 PTE 中设置 PTE_U 标志，因此只有内核可以使用它们。

每个进程的页表都同时包含用户内存和整个内核的映射，这在系统调用和中断期间从用户代码切换到内核代码时很方便：这样的切换不需要切换页表。内核在大多数情况下没有自己的页表；它几乎总是在借用某个进程的页表。

回顾一下，xv6 确保每个进程只能使用自己的内存。并且，每个进程看到自己的内存是从零开始的一段连续虚拟地址，而进程的物理内存可以是不连续的。xv6 实现前一点的方式是：只在指向进程自己内存的虚拟地址的 PTE 上设置 PTE_U 位。它实现后一点的方式是利用页表把连续的虚拟地址转换到恰好分配给该进程的任意物理页的能力。

代码：创建地址空间 ​

main 调用 kvmalloc (1840) 创建一张包含内核运行所需的 KERNBASE 以上映射的页表，并切换到它。大部分工作发生在 setupkvm (1818) 中。它首先分配一页内存来存放页目录。然后它调用 mappages 安装内核需要的转换，这些转换描述在 kmap (1809) 数组中。这些转换包括内核的指令和数据、直到 PHYSTOP 的物理内存，以及实际上是 I/O 设备的内存范围。setupkvm 不安装任何用户内存的映射；这将在稍后发生。

mappages (1760) 把一段虚拟地址到相应一段物理地址的映射安装到页表中。它按页的间隔，对该范围内的每个虚拟地址分别进行。对于每个要映射的虚拟地址，mappages 调用 walkpgdir 找到该地址对应 PTE 的地址。然后它初始化该 PTE，填入相关的物理页号、期望的权限（PTE_W 和/或 PTE_U），以及用于标记该 PTE 有效的 PTE_P (1772)。

walkpgdir (1735) 在查找虚拟地址对应的 PTE 时，模仿 x86 分页硬件的行为（见 图 2-1）。walkpgdir 用虚拟地址的高 10 位找到页目录项 (1740)。如果该页目录项不存在，那么所需的页表页尚未分配；如果 alloc 参数被置位，walkpgdir 就分配它，并把它的物理地址放入页目录。最后，它用虚拟地址接下来的 10 位找到页表页中 PTE 的地址 (1753)。

物理内存分配 ​

内核必须在运行时为页表、进程用户内存、内核栈和管道缓冲区分配和释放物理内存。

xv6 使用内核末尾到 PHYSTOP 之间的物理内存进行运行时分配。它一次分配和释放完整的 4096 字节页。它通过在页本身中穿入一个链表来跟踪哪些页是空闲的。分配就是从链表中摘下一页；释放就是把被释放的页加回链表。

这里有一个自举问题：为了让分配器初始化空闲链表，所有物理内存都必须被映射，而创建带有这些映射的页表又涉及分配页表页。xv6 的解决办法是在 entry 期间使用一个单独的页分配器，它只在内核数据段末尾之后分配内存。这个分配器不支持释放，并且受限于 entrypgdir 中 4 MB 的映射，但这足以分配第一张内核页表。

代码：物理内存分配器 ​

分配器的数据结构是一个空闲链表，由可供分配的物理内存页组成。每个空闲页的链表元素是一个 struct run (3115)。分配器从哪里获得存放该数据结构的内存？它把每个空闲页的 run 结构存放在该空闲页自身之中，因为那里本来也没有存放别的东西。空闲链表由一个自旋锁保护。链表和锁被包装在一个结构体中，以明确锁保护的是该结构体中的字段。现在请忽略锁以及对 acquire 和 release 的调用；第 4 章 将详细讨论锁。

函数 main 调用 kinit1 和 kinit2 来初始化分配器 (3131)。需要两次调用的原因是：在 main 的大部分执行期间，还不能使用锁或 4 MB 以上的内存。对 kinit1 的调用为前 4 MB 设置无锁分配，对 kinit2 的调用则启用锁并安排更多内存可供分配。main 本应确定有多少可用物理内存，但事实证明这在 x86 上很困难。它改为假定机器有 224 兆字节（PHYSTOP）物理内存，并把内核末尾到 PHYSTOP 之间的所有内存作为初始的空闲内存池。kinit1 和 kinit2 调用 freerange，通过逐页调用 kfree 把内存加入空闲链表。PTE 只能引用按 4096 字节边界对齐（即 4096 的倍数）的物理地址，因此 freerange 使用 PGROUNDUP 确保只释放对齐的物理地址。分配器一开始没有内存；这些对 kfree 的调用给了它一些可管理的内存。

分配器用物理页在高内存中映射后的虚拟地址来引用它们，而不是用物理地址，这就是 kinit 使用 P2V(PHYSTOP) 把 PHYSTOP（一个物理地址）转换为虚拟地址的原因。分配器有时把地址当作整数以进行算术运算（例如在 kinit 中遍历所有页），有时又把地址当作指针来读写内存（例如操作存放在每个页中的 run 结构）；这种对地址的双重用法是分配器代码中充满 C 类型转换的主要原因。另一个原因是，释放和分配本身就会改变内存的类型。

函数 kfree (3164) 首先把被释放内存中的每个字节设为值 1。这会使在释放后仍使用该内存的代码（使用“悬空引用”）读到垃圾数据而不是原来的有效内容；但愿这能让这类代码更快地出错。然后 kfree 把 v 转换为指向 struct run 的指针，把空闲链表原来的起始位置记录在 r->next 中，并把空闲链表设为 r。kalloc 摘除并返回空闲链表中的第一个元素。

地址空间的用户部分 ​

图 2-3 展示了 xv6 中正在执行的进程的用户内存布局。每个用户进程都从地址 0 开始。地址空间的底部包含用户程序的正文（text）、数据和栈。堆位于栈的上方，这样进程调用 sbrk 时堆可以扩展。注意，正文、数据和栈这几部分在进程的地址空间中是连续排列的，但 xv6 可以自由地为这些部分使用不连续的物理页。例如，当 xv6 扩展进程的堆时，它可以把任意空闲物理页用于新的虚拟页，然后编程页表硬件把该虚拟页映射到所分配的物理页。这种灵活性是使用分页硬件的一大优势。

栈只有一页，图中显示的是 exec 创建的初始内容。包含命令行参数的字符串，以及指向它们的指针数组，位于栈的最顶端。紧挨其下的是让程序能够从 main 开始执行的值，就好像函数调用 main(argc, argv) 刚刚开始一样。为了守护超出栈页继续增长的栈，xv6 在栈的正下方放置一个保护页。保护页没有被映射，因此如果栈越出栈页，硬件将产生异常，因为它无法转换出错地址。现实世界的操作系统可能会为栈分配更多空间，使其能够增长到超过一页。

代码：sbrk ​

Sbrk 是进程用来收缩或增长其内存的系统调用。该系统调用由函数 growproc (2558) 实现。如果 n 为正，growproc 分配一个或多个物理页，并把它们映射到进程地址空间的顶部。如果 n 为负，growproc 从进程地址空间解除一个或多个页的映射，并释放相应的物理页。为了完成这些改动，xv6 修改进程的页表。进程的页表存放在内存中，因此内核可以用普通的赋值语句更新它，allocuvm 和 deallocuvm 就是这么做的。x86 硬件在转译后备缓冲区（TLB）中缓存页表项，当 xv6 修改页表时，它必须使缓存的项失效。如果它不使缓存的项失效，那么此后的某个时刻，TLB 可能使用一个旧的映射，指向一个在此期间已被分配给另一个进程的物理页，结果某个进程可能得以在另一个进程的内存上乱写。xv6 通过重新加载 cr3（保存当前页表地址的寄存器）来使过期的缓存项失效。

代码：exec ​

Exec 是创建地址空间用户部分的系统调用。它从文件系统中存储的文件初始化地址空间的用户部分。Exec (6610) 使用 namei (6623) 打开指定的二进制文件 path，namei 在 第 6 章 中解释。然后它读取 ELF 头部。xv6 应用程序使用广泛采用的 ELF 格式描述，定义在 elf.h 中。一个 ELF 二进制由一个 ELF 头部 struct elfhdr (0905) 以及随后的一系列程序段头部 struct proghdr (0924) 组成。每个 proghdr 描述应用程序中必须装入内存的一个段；xv6 程序只有一个程序段头部，但其他系统可能为指令和数据设置单独的段。

第一步是快速检查该文件很可能包含一个 ELF 二进制。ELF 二进制以四字节的“魔数” 0x7F、'E'、'L'、'F' 开头，即 ELF_MAGIC (0902)。如果 ELF 头部具有正确的魔数，exec 就假定该二进制格式良好。

Exec 用 setupkvm (6637) 分配一张没有用户映射的新页表，用 allocuvm (6651) 为每个 ELF 段分配内存，并用 loaduvm (6655) 把每个段装入内存。allocuvm 检查所请求的虚拟地址是否低于 KERNBASE。loaduvm (1903) 使用 walkpgdir 找到所分配内存中用于写入 ELF 段每一页的物理地址，并使用 readi 从文件中读取。

用 exec 创建的第一个用户程序 /init 的程序段头部如下：

# objdump -p _init
_init:     file format elf32-i386
Program Header:
    LOAD off    0x00000054 vaddr 0x00000000 paddr 0x00000000 align 2**2
         filesz 0x000008c0 memsz 0x000008cc flags rwx

程序段头部的 filesz 可能小于 memsz，表示两者之间的空隙应当用零填充（用于 C 全局变量），而不是从文件中读取。对于 /init，filesz 是 2240 字节，memsz 是 2252 字节，因此 allocuvm 分配了足以容纳 2252 字节的物理内存，但只从文件 /init 中读取 2240 字节。

现在 exec 分配并初始化用户栈。它只分配一页栈。Exec 把参数字符串逐个复制到栈顶，并在 ustack 中记录指向它们的指针。它在将要传给 main 的 argv 列表末尾放置一个空指针。ustack 中的前三个条目是伪造的返回 PC、argc 和 argv 指针。

Exec 在栈页的正下方放置一个不可访问的页，这样试图使用超过一页的程序就会出错。这个不可访问的页还使 exec 能够处理过大的参数；在这种情况下，exec 用来把参数复制到栈上的 copyout (2118) 函数会注意到目标页不可访问，并返回 -1。

在准备新内存映像的过程中，如果 exec 检测到诸如无效程序段之类的错误，它就跳到标号 bad，释放新映像并返回 -1。Exec 必须等到确信该系统调用会成功之后才能释放旧映像：如果旧映像已经没了，系统调用就无法向它返回 -1。exec 中仅有的错误情形都发生在创建映像的过程中。一旦映像完成，exec 就可以安装新映像 (6701) 并释放旧映像 (6702)。最后，exec 返回 0。

Exec 把 ELF 文件中的字节装入内存中由该 ELF 文件指定的地址。用户或进程可以在 ELF 文件中放入任意地址。因此 exec 是有风险的，因为 ELF 文件中的地址可能（有意或无意地）指向内核。对一个不谨慎的内核来说，后果可能从崩溃到内核隔离机制被恶意颠覆（即安全漏洞）。xv6 执行若干检查来避免这些风险。为了理解这些检查的重要性，想一想如果 xv6 不检查 if(ph.vaddr + ph.memsz < ph.vaddr) 会发生什么。这是一项检查求和是否溢出 32 位整数的判断。危险在于，用户可以构造一个 ELF 二进制，其 ph.vaddr 指向内核，而 ph.memsz 足够大，使求和的溢出结果为 0x1000。由于和很小，它会通过 allocuvm 中的检查 if(newsz >= KERNBASE)。随后对 loaduvm 的调用单独传入 ph.vaddr，既不加上 ph.memsz，也不针对 KERNBASE 检查 ph.vaddr，因而会把 ELF 二进制中的数据复制到内核中。用户程序可以利用这一点，以内核特权运行任意用户代码。正如这个例子所示，参数检查必须非常小心。内核开发者很容易遗漏一项关键检查，而现实世界的内核有着悠久的遗漏检查的历史，这些缺失的检查会被用户程序利用来获取内核特权。xv6 很可能没有完整地验证提供给内核的用户级数据，恶意用户程序也许能够利用这一点来绕过 xv6 的隔离。

现实世界 ​

与大多数操作系统一样，xv6 使用分页硬件进行内存保护和映射。大多数操作系统使用 x86 的 64 位分页硬件（它有 3 级转换）。64 位地址空间允许比 xv6 限制更少的内存布局；例如，可以很容易地去掉 xv6 对物理内存 2 GB 的限制。大多数操作系统对分页的使用比 xv6 精细得多；例如，xv6 缺少从磁盘按需分页、写时复制的 fork、共享内存、延迟分配的页以及自动扩展的栈。x86 支持使用分段进行地址转换（见附录），但 xv6 只在一种常见技巧中使用段：实现 proc 这样的每 CPU 变量，它们位于固定地址，但在不同 CPU 上有不同的值（见 seginit）。在非段式体系结构上实现每 CPU（或每线程）存储时，会专门用一个寄存器保存指向每 CPU 数据区的指针，但 x86 的通用寄存器太少，因此为使用分段所付出的额外努力是值得的。

xv6 把内核映射到每个用户进程的地址空间中，但它的设置使得处理器处于用户模式时，地址空间的内核部分不可访问。这种设置很方便，因为进程从用户空间切换到内核空间后，内核可以通过直接读取内存位置轻松访问用户内存。然而，从安全角度看，更好的做法可能是为内核准备一张单独的页表，并在从用户模式进入内核时切换到该页表，从而使内核与用户进程彼此更加隔离。例如，这种设计有助于缓解 Meltdown 漏洞所暴露的侧信道，该漏洞允许用户进程读取任意的内核内存。

在拥有大量内存的机器上，使用 x86 的 4 MB“超级页”也许是有意义的。当物理内存较小时，小页是有意义的，可以以细粒度进行分配和换出到磁盘。例如，如果一个程序只使用 8 KB 内存，却分给它一个 4 MB 的物理页，那就很浪费。在拥有大量 RAM 的机器上，较大的页是有意义的，并且可能减少页表操作的开销。xv6 只在一个地方使用超级页：初始页表。该数组的初始化设置了 1024 个 PDE 中的两个，分别位于下标零和 512（KERNBASE>>PDXSHIFT），其余 PDE 保持为零。xv6 在这两个 PDE 中设置 PTE_PS 位，把它们标记为超级页。内核还通过在 cr4 中设置 CR_PSE 位（页大小扩展）来告诉分页硬件允许超级页。

xv6 应当确定实际的 RAM 配置，而不是假定 224 MB。在 x86 上，至少有三种常见算法：第一种是探测物理地址空间，寻找行为像内存的区域，即写入的值能够保持不变；第二种是从 PC 非易失性 RAM 中一个已知的 16 位位置读出内存的千字节数；第三种是在 BIOS 内存中查找作为多处理器表的一部分留下的内存布局表。读取内存布局表比较复杂。

内存分配在很久以前是一个热门话题，基本问题是高效利用有限的内存并为未知的将来请求做准备；见 Knuth。今天人们更关心速度而非空间效率。此外，更精细的内核很可能会分配许多不同大小的小块，而不是像 xv6 那样只分配 4096 字节的块；真实的内核分配器需要同时处理小的和大的分配。

练习 ​

  1. 考察真实操作系统，看看它们如何确定内存大小。

  2. 如果 xv6 没有使用超级页，entrypgdir 的正确声明应该是什么？

  3. 编写一个用户程序，调用 sbrk(1) 使其地址空间增长 1 字节。运行该程序，并考察调用 sbrk 之前和之后该程序的页表。内核分配了多少空间？新内存对应的 pte 包含什么？

  4. 修改 xv6，使内核的页在各进程之间共享，从而减少内存消耗。

  5. 修改 xv6，使用户程序解引用空指针时会收到一个错误。也就是说，修改 xv6，使虚拟地址 0 对用户程序不被映射。

  6. Unix 的 exec 实现传统上对 shell 脚本有特殊处理。如果要执行的文件以文本 #! 开头，那么第一行被当作解释该文件的程序。例如，如果调用 exec 运行 myprog arg1，而 myprog 的第一行是 #!/interp，那么 exec 就以命令行 /interp myprog arg1 运行 /interp。在 xv6 中实现对这一约定的支持。

  7. 删除 exec.c 中的检查 if(ph.vaddr + ph.memsz < ph.vaddr)，并构造一个利用该检查缺失的用户程序。

  8. 修改 xv6，使用户进程运行时只映射内核的最小部分，并让内核运行在自己的页表中，该页表不包含用户进程。

  9. 如果 xv6 运行在 64 位处理器上，你会如何改进 xv6 的内存布局？
